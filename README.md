# Telegram-чат через GREEN-API

Тестовое задание на React: подключение инстанса, создание чата по номеру телефона, отправка и получение текстовых сообщений в Telegram. Интерфейс использует компоновку веб-чата MAX: список чатов слева, переписка справа, поле сообщения внизу. Мессенджер реализации — **Telegram**, что допускает исходное задание.

## Локальный запуск

Нужен Node.js 22.12+ и npm. Перейдите в каталог проекта и выполните:

```sh
npm ci
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Переменные окружения, сервер приложений и база данных не нужны.

Чтобы проверить интерфейс без ключей, нажмите **«Посмотреть демо»**. Деморежим не делает запросов к GREEN-API и не отправляет сообщения в Telegram; ответ генерируется локально и явно помечен.

## Подключение Telegram

1. Создайте инстанс **Telegram** в [кабинете GREEN-API](https://console.green-api.com/). Доступ к API и настройки можно проверить в приложении ещё до входа в Telegram; для переписки затем авторизуйте аккаунт по QR в кабинете. Состояние для переписки должно быть `authorized`. Бот BotFather для этой реализации не нужен.
2. В настройках инстанса установите `incomingWebhook: "yes"`, очистите `webhookUrl`. Для обновления статусов исходящих сообщений включите `outgoingWebhook: "yes"`. После изменения настроек дождитесь их применения (кабинет предупреждает о сроке до 5 минут). Приложение проверяет настройки, но не меняет их автоматически.
3. Скопируйте `idInstance` в поле «ID инстанса», а `apiTokenInstance` в «Токен доступа». Адрес API предлагается по первым четырём цифрам ID: для префикса `4100` это `https://4100.api.green-api.com`. Сверьте его с `apiUrl` в кабинете. Если адрес отличается, откройте «Настройки подключения» и замените его в «Адрес сервера». Это подсказка по ID; источником адреса остаётся карточка инстанса.
4. Нажмите **«Подключить Telegram»**. Приложение проверит `getStateInstance` и `getSettings`. Если Telegram ещё не подключён, появится список готовности со ссылкой на карточку инстанса. Завершите вход по QR в кабинете и нажмите **«Проверить снова»**; данные в форме сохраняются, пока открыта вкладка.
5. Введите номер получателя с кодом страны, например `+79991234567`, и нажмите **«+»**. Если поиск по номеру запрещён приватностью Telegram, используйте публичный `@username`.
6. Напишите текст, нажмите Enter или кнопку отправки. Shift + Enter добавляет строку. Максимальная длина — 4096 символов.
7. Ответьте с аккаунта получателя в Telegram. Ответ появится в чате через очередь уведомлений.

Для проверки используйте отдельный тестовый инстанс и второй Telegram-аккаунт. Очередь GREEN-API общая для инстанса: другой потребитель уведомлений может забирать ответы раньше этого приложения. Не запускайте несколько вкладок с одним инстансом.

## Для кого этот чат

Приложение рассчитано на владельца Telegram-инстанса GREEN-API. В задании прямо предусмотрен ввод его собственных `idInstance` и `apiTokenInstance`. Это не форма входа в обычный Telegram: телефон, код входа и облачный пароль здесь не запрашиваются.

В обычном режиме показаны ID и токен с подсказками, где их взять. Адрес API доступен в сворачиваемых настройках. Переключатель «Режим разработчика» показывает технические названия полей и схему используемых методов; в подключённом чате также видны адрес сервера и ID инстанса. Токен остаётся скрыт.

Режим разработчика не выполняет дополнительные запросы и не меняет данные подключения. Схема методов не выдаётся за журнал запросов или подтверждение успешного тестирования. Переключатель не является механизмом контроля доступа.

## Реализация

React, TypeScript, Vite; стили на CSS без UI-фреймворка. Для переписки используется GREEN-API. На Vercel небольшой Express-сервер закрывает приложение паролем; запросы к мессенджеру по-прежнему идут напрямую из браузера. В приложении нет файлов, звонков, группового администрирования и других функций за пределами тестового.

| Действие                                     | Метод GREEN-API                                 |
| -------------------------------------------- | ----------------------------------------------- |
| Проверка авторизации                         | `getStateInstance`                              |
| Проверка настроек получения                  | `getSettings`                                   |
| Поиск Telegram chatId по телефону / username | `checkAccount`                                  |
| Отправка текста                              | `sendMessage`                                   |
| Получение уведомления                        | `receiveNotification?receiveTimeout=20`         |
| Подтверждение обработки                      | `deleteNotification/{receiptId}` методом DELETE |

Номер телефона разрешается в Telegram `chatId` перед отправкой. Данные чатов, черновики, сообщения и токен живут только в памяти вкладки и очищаются при выходе или обновлении страницы. Отправленные в Telegram сообщения при этом сохраняются в самом Telegram.

Получение выполняется одним последовательным циклом long polling. Повторное уведомление не создаёт дубликат сообщения. Сетевые ошибки вызывают повтор получения с задержкой до 30 секунд; при HTTP 400/401/403 цикл останавливается и предлагает переподключение. Выход отменяет запросы и таймеры. Текст с URL принимается как обычный текст; неподдерживаемые медиа и служебные события подтверждаются и пропускаются, чтобы очередь продолжала двигаться. Статусы исходящих обновляются по уведомлениям; без них сообщение остаётся с отметкой «В очереди».

Исходящее сообщение не отправляется повторно автоматически: после сетевого сбоя неизвестно, принял ли его сервер. Интерфейс предлагает проверить Telegram и вернуть текст в поле для ручного повтора.

## Данные доступа

Токен не записывается в localStorage, sessionStorage, URL страницы, репозиторий или переменные Vite. Запросы идут из браузера прямо в HTTPS API GREEN-API; адрес API ограничен доменами `api.green-api.com` и их серверными поддоменами. Ошибки провайдера и URL запросов не выводятся в интерфейс или журналы приложения.

Это браузерное приложение: владелец вкладки видит свои запросы и токен в DevTools. Для сервиса с общими серверными ключами нужен отдельный backend, сессии и серверное хранение секретов. Для тестового ключи вводит сам пользователь, как требует задание.

Уведомление подтверждается после передачи сообщения в состояние приложения. Постоянного хранилища и загрузки истории нет: обновление вкладки очищает уже отображённую переписку. Деморежим и тесты с имитацией HTTP не доказывают реальную доставку в Telegram.

## Проверки и сборка

```sh
npm test
npm run build
npm run preview
```

Тесты Vitest проверяют контракт запросов, поиск получателя, настройки инстанса, ошибки, дедупликацию, очередь с повторным подтверждением, отмену получения и полный сценарий React-интерфейса с имитацией HTTP. GitHub Actions запускает тесты и сборку при push и pull request.

`npm run build` создаёт каталог `dist/`. Локальный `npm run preview` показывает сборку без пароля.

## Публикация на Vercel с паролем

Проект использует preset Express, Node.js 22 и `vercel.json`. Сборка — `npm run build`; `outputDirectory` не задаётся. Сервер проверяет сессию перед выдачей HTML и каждого файла из `dist/assets`. Каталога `public/` нет: файлы не публикуются в обход проверки.

В окружениях Production и Preview нужны только серверные переменные:

- `REVIEW_ACCESS_PASSWORD` — общий пароль для проверки, минимум 8 символов.
- `REVIEW_SESSION_SECRET` — случайный секрет подписи сессии, минимум 32 символа.

Они не имеют префикса `VITE_` и не включаются в сборку браузера. Данные GREEN-API в ENV не нужны: пользователь вводит собственные ID и токен в приложении. При отсутствии настроек сервер закрывает доступ с ответом 503.

После ввода пароля сервер выдаёт подписанную cookie на 8 часов с `Secure`, `HttpOnly` и `SameSite=Lax`. Пароль передаётся только серверу этого сайта по HTTPS. Смена пароля или секрета отменяет прежние сессии; после изменения ENV нужен новый deployment.

Для локальной проверки сервера: скопируйте `.env.example` в `.env`, заполните два значения, затем выполните `npm run build` и `node --env-file=.env server.js`. Адрес — `http://127.0.0.1:3000`; опубликованная версия использует HTTPS. Файлы `.env` и `.vercel` исключены из Git. Не включайте пароль доступа в публичную документацию.
