# Соответствие заданию

Источник: [PDF задания](https://drive.google.com/file/d/1Ut39kkIs0QK-swnCsIPJc6pNqVIVGOD2/view), прочитан 15 октября 2026 года. Название: «Тестовое задание на должность — Фронтенд разработчик React (v5)». Срок из PDF: 5 дней; дата начала с работодателем здесь не согласована.

В PDF допускается Telegram вместо MAX. Выбран Telegram по решению кандидата. Обязательный сервис GREEN-API сохранён; используются методы из его Telegram API. Telegram Bot API не подменяет GREEN-API.

| Требование                         | Реализация                                           | Проверка                         |
| ---------------------------------- | ---------------------------------------------------- | -------------------------------- |
| React                              | React + TypeScript + Vite                            | Production build                 |
| GREEN-API                          | Прямые HTTPS-запросы к Telegram API сервиса          | Контрактные тесты                |
| Ввод idInstance и apiTokenInstance | Форма подключения с проверкой состояния              | Тест интерфейса с имитацией HTTP |
| Чат по номеру телефона             | checkAccount → Telegram chatId                       | Тест адаптера и интерфейса       |
| Отправка текста                    | sendMessage, до 4096 символов                        | Тест адаптера и интерфейса       |
| Получение ответа                   | receiveNotification → обработка → deleteNotification | Тест очереди и интерфейса        |
| Простой интерфейс по образцу MAX   | Список чатов, переписка, поле ввода                  | Ручная проверка браузера         |
| Удалённый формат работы            | Указан в README и черновике письма                   | Подтверждено кандидатом          |

## Проверка и сдача

Проверено 15 октября 2026 года:

- 28 тестов Vitest проходят: API-контракты, очередь, сценарии React и серверный доступ по паролю.
- TypeScript и production-сборка проходят.
- Реальные `getStateInstance` и `getSettings` проверены из браузера; настройки входящих уведомлений и очереди подтверждены.
- Авторизацию Telegram и реальный обмен сообщениями проверил пользователь, который подтвердил результат в переписке.
- В браузере проверены деморежим, обычная форма, режим разработчика и мобильная компоновка. Скриншоты в `docs/screenshots/` содержат только демоданные.
- Серверная защита проверяет пароль до выдачи HTML и файлов приложения; тесты покрывают неверный пароль, подделку и истечение сессии, отсутствие ENV и недопустимый источник формы.

Основная форма предназначена владельцу инстанса GREEN-API: ID и токен вводятся пользователем по условию задания. Адрес API доступен в сворачиваемых настройках и предлагается по префиксу ID; его нужно сверять с кабинетом. Режим разработчика показывает техническую справку, не журнал фактических запросов.

Репозиторий: https://github.com/Ndrewndrew/green-api-telegram-chat. Пароль опубликованной страницы передаётся отдельно в письме и не хранится в исходниках. Личные токены GREEN-API и облачный пароль Telegram в репозиторий не записывались.

Перед отправкой письма остаётся приложить актуальное резюме в PDF и указать Telegram для связи. Работодателю письмо автоматически не отправляется.

Опубликованная версия: https://green-api-telegram-chat-omega.vercel.app. GitHub и Vercel связаны: push в `main` запускает production-развёртывание.
